OPTIMIZATION NOTES:
════════════════════════════════════════════════════════════════════════════════

Performance Considerations:
  • Profiling runs on parquet file (compressed, so I/O efficient)
  • Classification: O(n) - scan all rows once
  • Profiling: O(n × m) where n=rows, m=columns (typically <100 cols)
  • Health scoring: O(m) - compute 5 dimensions per column
  • Total overhead: ~100-500ms for typical 1000-row files

Scalability:
  • Files <100k rows: Profiling in main thread (acceptable)
  • Files >100k rows: Could benefit from async/threading
  • Current implementation: Synchronous (best-effort, non-blocking)
  • Future enhancement: Make threading optional for large files

Database Insert Optimization:
  • Batch insert via profiling_repo.save_profiling_results(records)
  • ~4 records per typical file (one per column)
  • ~10-20 records for wide files (>20 columns)
  • DuckDB handles batch well, no bottleneck
