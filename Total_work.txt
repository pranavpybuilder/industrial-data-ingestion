1. PROJECT OVERVIEW
════════════════════════════════════════════════════════════════════════════════

This is a fully OFFLINE desktop application designed for industrial plant
operations teams. It ingests structured data from multiple industrial sources
(PLC telemetry, SAP PM orders, RFID logs, Excel reports, energy readings),
profiles the data, applies rule-based and ML-based analysis, generates
actionable insights, builds auto-generated dashboards, and exports reports —
all without any internet connection.

Key Principles:
  • 100% offline — no cloud dependency
  • DuckDB embedded database — zero setup
  • Desktop-first UI — React + Electron shell
  • Modular architecture — each layer is independently testable
  • Run-based workflow — every ingestion creates a "run" that flows through
    all downstream modules

Pre-Existing (already implemented before Module 1):
  • 4 Readers: csv_reader, excel_reader, json_reader, log_reader
  • 5 Source Ingestors: sap, plc, rfid, report_excel, operational_excel
  • 3 Validators: schema_validator, type_validator, time_validator
  • Versioning: run_id.py (UUID generator), data_versioner.py (Parquet)
  • 7 JSON Schemas: plc, sap_iw29, rfid, excel, report_excel, 
    operational_excel, power_cost
  • Storage: connection.py (DuckDB singleton), schema.sql (7 tables)
  • 6 Repositories: ingestion, run, insight, dashboard, export, profiling

Source Type Auto-Detection:
  The upload_handler.py automatically detects source types by:
  1. File extension matching (.csv, .xlsx, .json, .log)
  2. Column name peeking (reads first row headers)
  3. Pattern matching against known column sets per source
  
  Supported sources:
  • SAP     — SAP IW29 PM work orders
  • PLC     — Machine telemetry (temperature, pressure, vibration)
  • RFID    — RFID tag scan events
  • EXCEL   — Operational spreadsheets
  • ENERGY  — Power/cost readings

Pipeline Flow:
  1. User uploads file → upload_handler validates & auto-detects source
  2. Appropriate ingestor parses file → validates against JSON schema
  3. Data versioner creates Parquet file + metadata JSON
  4. Pipeline runner creates a new "run" in DB
  5. File metadata (schema_hash, row_count, columns) saved to ingested_files
  6. Numeric columns extracted as long-format features → feature_store table
  7. Run status updated to SUCCESS or FAILED

Testing:
  • PLC CSV (10 rows) — ingested successfully, schema hash c9ba2a05b14b9e74
  • SAP CSV (5 rows) — auto-detected correctly

Overview:
  After the frontend redesign, 214 problems appeared in the VS Code Problems

  │  name" (a11y: unlabeled selects)        │       │ + title attrs        │
  └─────────────────────────────────────────┴───────┴──────────────────────┘

Root Cause Analysis:
  1. Inline CSS warnings — The Edge DevTools extension's webhint linter
     flags React's style={} prop as "inline styles." This is a false positive
     for React applications, where inline styles via JavaScript objects are
     a standard pattern. Suppressed by creating .hintrc with the
     "no-inline-styles": "off" setting.

  2. Accessibility warnings — Genuine issues where interactive elements
     lacked proper accessible names for screen readers.
